# 项目方向卡：个人资金守护（Guardian）

**赛道 2 · Set It and Forget It（个人自动化）**
**单人开发**

## 一句话

监听 Sepolia 上指定钱包的 ERC-20 转出，单笔金额超过阈值就跨链回调到 Base Sepolia，
在链上留下可查的 Alert 记录并推送到即时通讯工具——一次配置，长期无人值守。

## 行业背景与问题

过去两年，自托管钱包的用户规模持续扩大，与此同时链上资产被盗、私钥泄露、授权钓鱼
的案例并没有减少。对个人用户来说，真正的风险窗口往往不是"没有感知"，而是
**"感知到了但来不及反应"**：异常转出发生在深夜、出差途中或开会时，人不在屏幕前。

现有方案各有短板：

| 方案 | 问题 |
|---|---|
| 人工盯区块浏览器 | 不可持续，注意力成本高 |
| 自建 Keeper 脚本 + 云服务器 | 要长期运维，私钥托管有风险，节点断连就漏报 |
| 付费监控服务 | 单价不透明，个人用户留存差 |
| 钱包内置风控 | 依赖厂商策略，规则不可自定义 |

Reactive 这类"事件驱动 + 跨链自动执行"的基础设施，恰好把这条链路里最重的部分
（监听、可靠性、发交易）交给网络，用户只需要定义"什么算异常、异常时做什么"。

## 技术方案

```text
① 源链 Sepolia：ERC-20 Transfer(from = 目标钱包, value ≥ 阈值)
② Lasna：react() 校验 from、阈值、剩余次数
③ 目标链 Base Sepolia：Callback 合约记录 Alert(金额, 源交易哈希, 时间)
④ 链下：监听 Alert → 推送通知（可选扩展）
```

几个设计取舍：

- **订阅阶段就把噪音过滤掉**：topic0 锁 Transfer、topic1 锁目标地址，避免全量事件烧钱。
- **阈值判断放在 `react()` 里用 `return`**：回滚同样收费，拒绝要"静默"。
- **双门锁**：`onlyServiceProvider` + `onlyCallbackSender`，防止任何人伪造回调。
- **成本可控**：按次计费（实测每次约 0.01 lREACT + 目标链 gas），可估算月度预算。

## 体验与心理设计

安全工具最大的敌人不是技术，是**告警疲劳**和**侥幸心理**：

- 默认只对"超过自设阈值"的单笔转出报警，不做全量通知；
- 告警分级（记录 / 推送 / 强提醒），避免"狼来了"；
- 首次配置引导用户把阈值设高一点，宁可漏报轻微异常，也不要让用户三天后关掉通知；
- 明确写出"本工具不冻结你的资产"，避免用户产生"装了就等于安全"的错觉。

## 商业模式与成本

- 个人版：自托管 + 免费，成本主要是 lREACT 与目标链 gas，按次约几分钱；
- 团队版：多钱包订阅、阈值策略模板、通知渠道集成（Telegram / 飞书 / 邮件），按月订阅；
- 与钱包/托管方合作：作为"链上侧的风控信号源"，不碰私钥，只输出告警事件。

## 最小 Demo（第 2 周结束前）

Sepolia 发一笔超过阈值的测试代币转账 → Lasna `react()` 判断 → Base Sepolia
回调合约 emit `Alert(amount, originTxHash)`，链上可查；链下推送为加分项。

## 边界与风险

- 只能"事后告警/记录"，**不能撤销已经发生的转账**，也不承诺追回资产；
- 不做"自动转移资产"这类高风险动作（需要授权，超出个人自动化边界）；
- 所有演示在测试网完成，不涉及真实资金。
