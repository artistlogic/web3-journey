# 项目方向卡：个人资金守护（Guardian）

**赛道 2 · Set It and Forget It（个人自动化）｜单人开发**

## 一句话

监听 Sepolia 上指定钱包的 ERC-20 转出，单笔超过阈值就跨链回调到 Base Sepolia，
在链上留下可查的 Alert 记录并推送通知——设置一次，之后不用管。

## 目标用户与真实场景

自托管钱包的用户在变多，但异常转出经常发生在深夜、出差或开会时，人不在屏幕前。
现在的做法都不太合适：人工盯浏览器不可持续；自建 Keeper 脚本要长期运维、
私钥托管有风险；付费监控服务单价不透明。

Reactive 把"监听 + 可靠发交易"交给网络，用户只需要定义"什么算异常、异常时做什么"。

## 最小 Demo（第 2 周结束前跑通）

```text
① Sepolia：测试代币 Transfer(from = 目标钱包, value ≥ 阈值)
② Lasna：react() 校验 from、阈值、剩余次数
③ Base Sepolia：Callback 合约 emit Alert(金额, 源交易哈希) → 链上可查
④ （加分）链下监听 Alert → Telegram 推送
```

第 ③ 步跑通即为最小闭环。

## 几个关键设计

- 订阅阶段就过滤：topic0 锁 Transfer、topic1 锁目标地址，不订全量事件
- 阈值判断用 `return` 不用 `revert`（回滚同样收费）
- 回调双门锁：`onlyServiceProvider` + `onlyCallbackSender`
- 次数上限，用完自动 `unsubscribe`；余额不足前 `depositTo`

## 边界

只做事后告警与链上记录，不能撤销已发生的转账，也不承诺追回资产；
不做自动转移资产这类高风险动作。所有演示在测试网完成。
